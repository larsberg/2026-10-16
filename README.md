# 2026-10-16

Prepared for GitHub Pages at `https://larsberg.github.io/2026-10-16/`, with source repository `https://github.com/larsberg/2026-10-16`. These are publishing targets; the repository and Pages site still need to be created.

A dodecahedron-based polygon mesh with n-sided face editing, bone-chain physics, and the metallic mesh finish from `2026-10-08-blobby`. A wireframe overlay is available in the controls.

```sh
npm install
npm run dev
```

Open `http://127.0.0.1:1234/`. `npm run check` runs silent Node tests and a production build.

The drawer, tabs, fields, Save/Reload API, studio settings, info editor, player bridge, and Three.js perspective camera with OrbitControls come from `2026-10-13`. The starting camera frames the free-moving body above a visible ground plane. The Blobby-style framed ground info panel is visible and reads from the four rich-text Info fields. Its date, description, SUUNS credit, and technology credits are editable through the same settings system. Box3D `0.2.0` supplies rigid-body bone chains using the cone-joint approach from `2026-09-25-rectaspinulator`. There is no soft-body simulation.

**Mesh → Dodecahedron radius** ranges from **0.5–4**, defaults to **2**, and persists as `mesh.radius` through the same CMS/settings system. The starting mesh has **12 pentagons, 20 shared vertices, and 30 edges**. It is closed, with no border. Older grid saves migrate to the dodecahedron, enable the ground, and frame the body while retaining the existing material, audio, and operation settings.

The dodecahedron passes through these **Operation layers**, in order:

1. Apply an **initial Diamond dual** to the dodecahedron. Each shared edge becomes a quad. The existing boundary-preservation behavior still applies to manually edited open meshes.
2. Triangulate every quad, choosing its diagonal independently at random. Existing border triangles stay triangles.
3. Apply the **face-center dual**: connect neighboring face centers around each original vertex.
4. **Average vertices** once: replace each interior vertex with the arithmetic mean of its unique edge-connected neighbors. All averages use the original positions simultaneously. Boundary vertices retain their exact XYZ positions; topology and face eligibility stay unchanged. This pass is enabled by default and runs before inset.
5. Select eligible faces and extrude with zero depth and a **0.5** scale about each face's center, forming an inset cap and surrounding faces. **Exclude initial border triangles from inset / extrusion** starts enabled: original border triangles remain in the mesh, and their descendants are skipped. A face-center dual cell is skipped if any incident source face came from an original border triangle. Triangles created from interior quads remain eligible. Concave cells use a center inside their visibility kernel so their insets stay inside the face.
6. Sample an **extrusion amount** from the minimum/maximum range (default **1–3**) and use **max(1, floor(amount)) segments per piece**. **Extrusion length per segment** sets each segment’s actual scene length from **0.01–1.0**, default **1.0**, persisted as `pipeline.segmentLength`. Total depth is segment count × segment length: amount 3.8 produces three segments, so length 0.25 produces depth 0.75. Changing the length preserves the seed and segment counts while rebuilding the mesh, bones, joints, and fitted colliders. The former fixed segment-count slider is removed; older saves default to length 1.0 and ignore their saved segment count.
7. **Subdivide & smooth** the entire surface with one [Catmull–Clark](https://opensubdiv.org/docs/subdivision_surfaces.html) pass by default. Each n-sided face becomes n quads. Interior vertices and edges smooth; existing boundary vertices stay fixed and boundary edges split at their exact midpoints. Concave faces use an interior subdivision center; a smooth update that would fold a quad is reduced toward linear subdivision. The refined descendants of the caps remain selected.
8. Apply the **Diamond dual** to the smoothed surface: one diamond quad across every shared edge, with triangles along the open boundary to retain the outline. This replaces all faces and clears the previous cap selection.
9. **Triangulate before Hexelate** splits the current faces into triangles, choosing diagonals from a separate seeded random stream. This is an explicit, independent pass after the diamond dual, and also works when the diamond pass is off. It adds no vertices and preserves bone weights.
10. **Hexelate** applies a direct **face-center dual**, joining neighboring triangle centers around each vertex into polygon cells, predominantly with five to seven sides. It preserves the open boundary and interpolates bone weights onto the new vertices. Disable the preceding triangulation to take a direct dual of the quad mesh instead; that produces mostly quads. The Mesh tab reports final face counts by side count; **Mesh wireframe** displays the actual polygon edges.
11. **Average vertices after Hexelate** performs one simultaneous neighbor-average pass on the final mesh. Boundary XYZ positions, face loops, selection, and skin weights remain unchanged. This runs last and has its own toggle, `pipeline.finalAverageVerticesEnabled`.

The existing drawer/settings system stores these controls in `pipeline`. All eleven passes have independent, numbered on/off toggles, enabled by default. Enabled passes run in their original order; disabled passes pass the current mesh through. **Average vertices (fixed boundary)** persists as `pipeline.averageVerticesEnabled`; **Hexelate** persists as `pipeline.hexelateEnabled`, and its preceding triangulation as `pipeline.hexelateTriangulateEnabled`. Turning off Inset lets extrusion target the current faces directly. Turning off Extrusion leaves the central body. Accepted combinations retain the original boundary; averaging and smoothing keep boundary vertices fixed. Toggles persist through Save/Reload and are reapplied on resize. The random seed reproduces the diagonal choices and face depths; **New variation** changes it. **Subdivision passes** controls smoothing iterations (1–3, within the existing 50,000-face limit). Disable **Apply operation layers** to inspect the twelve base pentagons. `mesh.layers` exposes enabled stage counts and, when extrusion is enabled and both final duals and the final triangulation are disabled, original extrusion depths inherited by each selected cap descendant.

With inset and smoothing both disabled, independently extruded adjacent faces can leave coincident walls. If the new triangulation and dual would produce an untriangulatable folded polygon, the control change is rejected and the previous settings and mesh are restored.

The border-exclusion setting follows face ancestry through triangulation and the face-center dual, rather than excluding every triangle by its side count. It applies to both inset and depth extrusion, including when either pass is disabled. It has no effect when the initial diamond pass is disabled. Subsequent subdivision/smoothing and the final diamond dual still operate on the whole mesh; the outer boundary remains fixed, while the interior rim may blend toward neighboring raised faces during smoothing. Disable the exclusion to restore extrusion of every face.

**Motion → Bones & colliders** builds one bone chain for each piece created by the depth extrusion pass. Each extrusion segment has one scaled **capsule collider** and one dynamic bone. The shared capsule template has total length **1**, radius **0.25**, and shaft length **0.5**. Its transverse scales come from the extruded face bounds, aligned to the face's first edge; its axial size starts with the extrusion segment length. **Joint overlap (× radius)** defaults to **1**: each shared joint is inset half the smaller transverse radius into each neighboring capsule. The resulting overlap is one radius, while the first capsule stays above the base and the last capsule keeps the original tip. Set overlap to zero for the previous end-to-end placement. Short segments keep their full face footprint, with compressed rounded ends. These dimensions are captured before smoothing and dual operations. An asymmetric face offsets its collider to the footprint center while preserving the original bone and joint positions. Physics uses a convex hull of the same scaled rounded template, so collision, hover picking, and green debug outlines agree. The physics world normalizes the extrusion segment to one unit and converts positions, joint anchors, gravity, impulses, and density back to scene dimensions; this also keeps small shapes above engine tolerances. Every chain starts at an anchor fixed in the central body’s local coordinates. The shared body translates and rotates freely; the roots move with it. Spherical joints connect the central body and each successive segment, with cone limits (60° by default) and twist limits (±90°). Connected colliders and members of the same chain do not collide with one another; different chains can collide.

Each rig includes a **200 × 200 scene-unit ground collider** aligned with the visible floor at world **Y = 0**. The central convex hull and piece capsules collide with it; restitution produces a physical rebound. The central hull is kept inside the base surface and capped at 32 vertices to respect the physics engine’s hull limits. Regeneration spawns the form above the floor. `mesh.rig.core` exposes the dynamic central body; `.basePlane` exposes the ground collider.

The finished mesh is bound to a Three.js skeleton. Extrusion rings establish its weights; subdivision and the final diamond dual interpolate those weights while retaining up to four influences per vertex. The unextruded surface binds to the central body bone. The shaded surface, wireframe, and selection buffers use the resulting skinned positions, and face picking follows the same pose. Bones are cyan; joint points are amber; collider capsules are green. Their visibility toggles, simulation, gravity, joint limits, density, and binding toggle persist under `rig` in the existing settings system. **Linear damping** and **Angular damping** independently damp translation and rotation, default to 1, and update existing bodies without resetting the pose. Older saves with a single `damping` value migrate it to both controls. Gravity defaults to 9.8. The central body uses 15% of the chain damping so it can roll and bounce. **Nudge bone chains** applies a small impulse to inspect movement and skin deformation. Existing Play/Pause controls also pause physics; Restart rebuilds the original rig and pose.

**Materials → Mesh · Blobby finish** reuses Blobby's `MeshPhysicalMaterial`, saved metalness **0.88**, roughness **0.37**, clearcoat **0.45**, and clearcoat roughness **0.16**. Its **Flat → smooth normals** control starts at **0.47** and blends each whole polygon's flat normal with shared-vertex smooth normals while Flat shading is enabled. Turning Flat shading off uses smooth normals. The polygon normals follow the bone-deformed surface. These material controls use the existing Save/Reload system. **Mesh surface** and **Mesh wireframe** visibility are independent; the surface starts visible and the wireframe starts hidden. The sketch retains its current lighting and black background.

**Lighting → Studio palette** retains Blobby's eight palettes, previous/next buttons, editable studio colors, and half-second fades. The same seven-panel studio bakes the environment reflection textures; intensity and rotation remain editable. Choosing a palette colors the reflections, background, and lights together, exactly as in Blobby. Save/Reload retains custom colors and reflection settings; the initial background remains black.

The mesh contributes to **Contact shading · GTAO**, including in **AO only** preview. Guide lines are excluded through layers so their solid mesh children remain visible to the AO pass. The directional shadow camera fits the current bone-deformed surface every frame and after regeneration. Disable **AO only** to see the material and cast shadows together.

**Repel colliders on hover** is enabled under **Motion → Bones & colliders**. Hovering the canvas raycasts the moving capsule colliders, including hidden collider outlines, and accelerates the nearest hit body sideways away from the pointer ray at its depth. **Hover acceleration** defaults to **14 scene units/s²**. The impulse scales with body mass and the fixed physics timestep. Roots stay attached to the moving body. Pointer leave, touch, orbit drags, window blur, and Play/Pause suspend hover forces. The toggle and strength persist through Save/Reload. Rebuilding the mesh automatically reconnects hover to its new rig.

**Mesh → Maximum chains** caps the actual extruded pieces at **32** by default and can be lowered to **1**. When there are more eligible faces, deterministic spatial sampling spreads the chosen pieces around the body; unchosen faces remain in the connected base. Resize and mesh regeneration respect the cap.

**Drag a piece or the central body** to lift, translate, and toss the whole form. A solver spring joins the picked point to the cursor, letting the chain joints carry and rotate the body. **Motion → Grab response** controls **Grab stiffness** (1–60 Hz, default 30) and **Grab damping** (0–2, default 0.75). Higher stiffness follows faster; lower damping adds bounce. Release retains the motion generated by the drag. The held chain keeps its current scale until release, so random notes do not shrink the collider out of the grab. Root anchors and cone joints remain constrained. The grab follows a camera-facing plane and captures the pointer, so release outside the canvas still ends the grab. Empty-space drags orbit the camera; Shift-click selects faces. Pause, blur, pointer cancellation, rig rebuild and disposal all release the grab and end its audio response.

Changing extrusion amounts or segment length, mesh layers, seed, or viewport dimensions rebuilds colliders, joints, bones, and binding together. Disabling extrusion creates no chains. Manual topology edits suspend the procedural rig; Undo restores its binding, and regeneration rebuilds it. `window.__meshSketch.mesh.rig` exposes the current skeleton, bodies, cone joints, statistics, and `nudge()`; each `.rig.links` entry exposes its fitted `halfExtents`, template `capsuleScale`, and local `colliderOffset`; `.binding` exposes chain definitions and vertex weights. `rig.physicsScale` converts scene lengths into physics lengths; native bodies and joint frames use those physics units. The canonical `.topology` stays in its bind pose while rendering and picking use the deformed positions.

Container resizing regenerates the dodecahedron and operation layers, disposing previous buffers. The body keeps a world-aligned up direction, independent of the camera. Radius, field-of-view, layer edits, Reload, and Restart also regenerate it and clear manual edits. Camera Follow tracks the moving body and suspends during grabs so the drag plane stays steady.

**Motion → Music response** sorts chains by original extrusion volume (face area × total depth), reserves the largest **33% for bass** (nearest whole chain), and shares the rest evenly between the other instruments in register order. Each note drives every chain in its instrument group, so chains do not wait for a particular pitch to occur. The note palette is derived from the Strudel pattern and rebuilt with the mesh or a replacement composition. A bass-only score uses every chain; very small meshes route any unrepresented instrument to the nearest available register.

The **Minimum bone scale** and **Maximum bone scale** sliders set the resting size and the strongest note-hit peak. They default to **0** and **1.2**, each independently range from 0 to 2, and save with the other rig settings. Neither slider restricts or changes the other; reversed values make notes shrink toward the hit scale and return to the resting scale. Zero minimum collapses chains between notes. Each note's envelope moves between those limits, with pitch weights from **1.0 for the lowest note to 0.1 for the highest** and quieter notes producing smaller peaks. Note weight influence (default 0.2) controls the variation in hit size between pitches, staying between the two chosen endpoints. The weight endpoints, attack and release remain editable. Older saves migrate their previous extra peak scale into the new maximum, preserving their motion. Scale multiplies down the hierarchy: a local factor of 0.5 produces cumulative factors 0.5, 0.25 and 0.125; a full-strength low note peaks at 1.2, 1.44 and 1.728. Native collision hulls and joint frames resize with the skeleton. During simulation, changing the joint anchors drives growth through the physics solver; active bodies are not repositioned from the root. Ground contacts can therefore brace the chains and push the central body. Scaling preserves each link’s mass, and newly activated links inherit their parent’s motion. The free-body rig updates growth and physics at 240 Hz with firmer contact recovery for gravity settings up to 100. Bodies below 5% of their original dimensions are suspended until they expand again, avoiding degenerate hulls and phantom contacts or hover hits at zero scale. Roots and the unextruded surface follow the central body. Pausing holds the current pulse; disabling note scaling restores unit scale. A rig without assigned notes also retains unit scale.

**Push chains on notes** adds an upward and sideways impulse to the matching physical chains, with varied directions per hit and more movement toward the tips. **Note push strength** defaults to **4**, ranges from **0–20**, and saves with the other Motion settings. Impulses are normalized by mass and segment length, with roots attached to the moving body. Collapsed links receive their push once they grow large enough for physics; each hit pushes each link once. Pushes work independently of scale animation and require the bone simulation to be enabled. Setting strength to zero or disabling the push toggle stops new note forces.

**Audio → Guitar / high instruments** and **Voice / lead** are expanded by default. Both expose sound selection, level, decay, filter cutoff/resonance, distortion, reverb, delay time/level and feedback through the existing settings system.

**Audio → Chaotic notes while dragging** temporarily replaces the song with random notes played through the existing instruments and effects. **Drag notes per second** defaults to **32** and ranges from **8–64**. Releasing cancels scheduled and sounding random notes, then resumes the normal song at its current beat; the song clock never restarts. The existing audio enable, volume and instrument mute controls still apply.

Environment colors and brightness stay constant during notes and dragging. Studio palette choices, editable colors, reflection intensity, rotation, and manual palette fades remain available.

**Audio → Enable audio** plays an evolving arrangement of the existing SUUNS “Look No Further” study. `src/arranged-score.js` moves intact two- and four-bar ensemble phrases from `src/reference-score.js` into a deterministic, changing sequence. Every original note, instrument assignment, onset, duration, gain, and procedural sound seed stays intact inside its phrase. Tails continue across section boundaries. The arrangement alternates contrasting section families and varies phrase lengths, instead of repeating the 80-bar form. Your tempo, instrument sounds and effects remain active. Source analysis remains in `analysis/look-no-further/index.html`. Audio remains off by default; Play/Pause, tab visibility and the existing gesture unlock govern playback. `window.__meshSketch.setComposition(pattern)` can replace the score.

**Lighting → Following spotlight** is the main shadow-casting light. Both its position and aim follow the body each frame; its offsets remain in world space as the mesh rolls. Color, intensity, offsets, cone angle, edge softness and shadow settings use the existing Save/Reload system and studio palettes. The directional light starts disabled. The floor receives direct light and shadows but has no environment reflections, including on beveled tiles.

`window.__meshSketch.mesh.topology` exposes `{ vertices, faces, kind, radius }` for subsequent editing. Vertices are local XYZ arrays; faces are ordered vertex indices of any length. Call `mesh.refresh()` after changing topology to redraw boundaries. The API also exposes camera, controls, renderer, playback, and settings.

Save/Reload writes `public/setup.json` in development and URL-scoped device storage in production. Only test rendering in a visible, user-controlled, muted browser. Never start background or headless audio playback.

The **Mesh** tab now includes four editing operations:

- **Triangulate faces** splits each target polygon into triangles, including concave n-gons, preserving its winding and existing vertices. The face is projected into its local plane and triangulated with [Three.js ShapeUtils](https://threejs.org/docs/pages/ShapeUtils.html).
- **Dual mesh → Diamond** places a quad across each shared edge, joining its endpoints and the centers of the two neighboring faces. Open boundary edges produce triangles so the original outline remains intact. This is the edge-based [join construction](https://www.georgehart.com/virtual-polyhedra/conway_notation.html).
- **Dual mesh → Face-center dual** joins face centers in connectivity order around every original vertex. On an open mesh, shared boundary-edge midpoints and original corners close the boundary cells without shrinking the outline. Duals act on the whole mesh and require consistent face winding and manifold vertex fans.
- **Extrude faces** replaces each target face with its transformed n-sided cap and one side quad per edge. Faces extrude independently, including adjacent selected faces. They can therefore have coincident side walls when their transforms line up. The transform applies scale, XYZ rotation, then translation in a local frame whose origin is the arithmetic mean of the face's vertices: X follows its first edge, Y lies in its plane, and Z is its normal. Negative depth extrudes inward. Positive X/Y scales avoid collapsed caps; invalid or degenerate results are rejected without replacing the current mesh.

Click a face to select it; Shift-click toggles more faces. Selected polygon edges are amber on both shaded and wireframe views. **Only selected faces** restricts Triangulate and Extrude to that selection. Otherwise those operations affect all faces. **Select all**, **Clear selection**, and **Undo** are in the same Mesh tab. Undo retains up to 20 edits; edits are limited to 50,000 faces per operation. Orbit gestures continue to use the existing camera controls.

Manual editing controls persist through the existing settings system as `editing` and `extrusion`. Older saves acquire defaults for these groups and new `pipeline` controls. **Only selected faces** starts enabled; select faces after the diamond dual before further editing. Resizing, changing the base radius or operation layers, Reload, or Restart rebuilds the procedural mesh and clears manual edits and undo history. Save retains controls and the seed, not manually edited topology.

`window.__meshSketch.mesh` exposes `selectFaces(ids)`, `selectedFaces`, `triangulate(ids?, { random }?)`, `dualDiamond()`, `dualNSided()`, `extrude(ids?, transform?, { segments }?)`, and `undo()`. Omitting face IDs means all faces; an empty list means none. Extrusion accepts an invertible affine Three.js `Matrix4` in each face's local frame, or a callback `(faceId, frame) => matrix` for per-face transforms. `extrusionTransform(options)` in `src/mesh-operations.js` creates the same transform used by the controls. Pure operations in that module return `{ mesh, faceIds }`, where `faceIds` identifies resulting triangles or extrusion caps. The operations preserve their input mesh. The optional `segments` argument accepts an integer or a callback `(faceId, frame) => integer`; procedural extrusion uses this callback for the amount-derived segment count.

The pure operation `subdivideSmooth(mesh, selectedIds?, { iterations }?)` refines the whole mesh and propagates the supplied selection to child faces. Its `sourceFaces` array maps each resulting face back to its input face. Subdividing the whole surface keeps adjacent faces connected even when only caps are selected.


Controls start fully hidden, including the drawer button and frame-rate meter. Press **H** to show or hide them, or open `?ui=1` to show the drawer button. The same behavior applies to the embedded player.

To record, press **R** to start/stop, or use **H → Info → Record video & audio**. After stopping, click **Download video**. The recorder captures only the rendered canvas and the sketch's final stereo audio output after effects, volume, compression and limiting. Enable audio first to include the song. No microphone or screen-sharing permission is needed. It selects MP4/H.264/AAC when supported and otherwise WebM/VP9 or VP8 with Opus. Choose a target of 30 or 60 fps; actual frame rate follows rendering performance. The long side is capped at 1920 pixels, and the initial recording dimensions remain fixed across window resizes. Controls and the recording badge are excluded. Hiding the tab ends the clip; a 256 MB cap bounds in-memory buffering. Clips stay local and are not uploaded. ## Publishing and gallery data

`public/sketch.json` is the metadata source: title, creation date, author, description, tags, technologies, audio gesture requirement, thumbnail, repository, standalone URL, and the `sketch-player:v1` embed contract. The title remains **2026-10-16**, dated **October 16, 2026**. Change the title here before building if it gets a name later.

`public/thumbnail.png` is the supplied **1189 × 699** image, preserved unchanged. The build uses it for both the gallery thumbnail and Open Graph/Twitter previews. `index.html` receives the full social metadata, canonical URL, and a link to `sketch.json` at build time.

Run `npm run check` to run the silent Node tests and build `dist/`. The build includes `sketch.json`, `catalogue.json`, `site-entry.json`, `setup.json`, the thumbnail, bundled JavaScript/WASM, and `.nojekyll`. It requires no development server in production. Local Save writes `public/setup.json`; published Save stores settings on the viewer's device. Rebuild and republish after changing the default settings.

For the first publication, create the public GitHub repository and connect this checkout (there is no `origin` yet):

```sh
gh repo create larsberg/2026-10-16 --public --source=. --remote=origin
npm run deploy
gh api --method POST repos/larsberg/2026-10-16/pages -f 'source[branch]=gh-pages' -f 'source[path]=/'
```

The last command enables Pages for the first time; GitHub Settings → Pages → Deploy from a branch → `gh-pages` / root does the same. Later releases only need `npm run deploy`, which runs tests and builds before pushing `dist/` to `gh-pages`. Commit and push source changes separately to retain the editable project on GitHub.

Once the standalone URL is serving successfully, add the generated **`dist/site-entry.json`** object to the `sketches` array in **`../lasersite/content/sketches.json`**. That is the gallery's current editing source; the older hosted-manifest registration files are no longer read. The generated entry contains the ID/slug, title/date, exact thumbnail dimensions and alt text, absolute standalone/embed URLs, iframe permissions, technologies, and the same sidebar defaults as Blobby Buddies. It is regenerated from the manifest on every build, so those fields stay synchronized. If the entry is staged in the gallery before the runtime is live, set `hidden` to `true` until deployment is verified.

The gallery entry's runtime URL is `https://larsberg.github.io/2026-10-16/?embed=1`. The gallery appends `parentOrigin` for its cross-origin player messages. Play, pause, reset, and setup/save/load use the existing bridge; audio requires a user gesture. Controls start hidden; **H** reveals them. Gallery publishing is separate from publishing this sketch.
